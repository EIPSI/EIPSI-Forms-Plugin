# Native Assessment Editor v0

Historical phase documentation; current implementation: [Product & Runtime Completion](product-runtime.md). Historical gaps below are not the current feature inventory.

**V0 IMPLEMENTED — AWAITING PRODUCT REVIEW.** Parallel prototype, not a replacement for Gutenberg and not a new participant runtime.

Open **EIPSI Forms → Assessment Editor**, or `/wp-admin/admin.php?page=eipsi-assessment-editor`, with an administrator account. No container restart is required when the plugin directory is bind-mounted; reload the page. JS/CSS versions use their file modification time.

## Architecture and boundaries

`src/admin/assessment-editor/{model,widgets,preview,app}.js` are four plain JavaScript modules, composed in manifest order by `scripts/build-form-runtime.js` into `assets/js/assessment-editor.js`. No framework, drag library, Gutenberg API, new npm package or serialization of blocks. `widgets.js` supplies controls to both canvas and preview. Existing participant consumers remain independent; future convergence needs explicit response/presentation adapters and review.

`includes/assessment-editor` contains the native DTO validator, dedicated repository, admin transport and an explicit Engine mapper. Main bootstrap loads these services only on the new admin screen or its AJAX action. The menu is the only new entry in the existing administration. The original phase used `manage_options`; current administrative access uses the action capabilities in [permissions and roles](../permissions-and-roles.md).

## Native state and schema

```json
{
  "contract": "EIPSI_ASSESSMENT_V1",
  "id": "AE_stable_identity",
  "title": "Evaluación",
  "elements": [{
    "id": "EL_stable_identity",
    "type": "text",
    "response_key": "R_stable_identity",
    "properties": {"label": "¿Cómo estás?", "helper": "", "required": true,
                   "placeholder": "", "max_length": 2000},
    "options": [],
    "children": []
  }]
}
```

Elements: `text`, `textarea`, `single_choice`, `multiple_choice`, `likert`, `vas`, `instruction`, `image`, `group`, `page_break`. All properties are typed and type-specific; unknown fields are rejected. Common label is plain text, never executable HTML. Questions have helper and required; text types also placeholder and maximum length. Choice types have `presentation` (`vertical`/`horizontal`) and ordered `{id,label}` options. Likert points derive from options. VAS stores finite min/max/step/initial, left/right labels and show_value; bounds and initial must align with step. Image is a placeholder with alt/caption. Groups have label and children; non-groups cannot contain children. Content has null response_key. PageBreak has fixed label and no answers, options, children or targets.

IDs and response keys are generated with browser cryptographic randomness, independent of labels. Editing and moving preserve identity. Explicit `cloneIdentity` renews element IDs, question keys and option IDs recursively. Options retain IDs through label changes/reordering. Arrays define order; canonical JSON sorts object keys recursively and preserves arrays. Contract version is the future migration boundary; v0 rejects unknown contracts rather than silently migrating or dropping fields. Future element types require explicit validator/widget/mapper additions.

Editor state additionally holds selected ID, loaded revision, dirty/saving state and transient drag payload. None are saved in the DTO. Server limits: 300 elements, depth 8, 100 options per choice, bounded strings and 1 MiB request. PageBreaks are assessment-level only in v0; groups are kept within one page. Consecutive separators intentionally project empty pages. There is no persisted Screen/page entity.

## Persistence and authorization

Dedicated **non-autoloaded wp_options** entries `eipsi_native_assessment_<id>` hold canonical JSON `{definition,revision,updated_at}`. This avoids schema migrations, CPT registrations and changes to Study/legacy tables or post_content. The simple library shows the latest 100 entries by creation order; pagination, deletion and search are deferred. Existing entries beyond that limit are not deleted.

New save requires revision 0 and atomic add_option. Updates compare the loaded revision and atomically compare the previous stored JSON in SQL before incrementing revision; stale saves return HTTP 409. Reopen to resolve a conflict; no merge or overwrite. Every repository method checks administrator capability. AJAX requires authenticated administrator, POST, valid nonce and, when supplied, a matching Origin scheme/host/port. Lists/loads also require the nonce. Unauthenticated AJAX has no nopriv handler. Client parses server errors visibly; failed saves retain current edits. Manual save only. A beforeunload warning protects dirty edits. No publication action exists.

## Interaction and DnD

Three areas: categorized palette, visual canvas and contextual inspector. Click insertion goes after the current element or into the selected group; PageBreak insertion finds the outer group boundary. Own HTML Drag and Drop API uses `application/x-eipsi-assessment` payloads. Drop zones exist at all sibling boundaries and inside empty groups; drops modify the model, never derive canonical state from DOM order. Moving a group into itself/descendants is rejected before mutation. Drag begins on each element's Mover handle to keep text inputs editable.

Buttons ↑/↓, Mover al grupo and Sacar del grupo provide keyboard-accessible alternatives. Option rows use add/remove/up/down rather than CSV. Direct label, instructions, options and section-title editing preserves focus while typing. Inspector exposes required/helper/placeholder/options/presentation/VAS settings; technical IDs are under Avanzado. Duplicate and delete are immediate. Undo/redo and drag-reordering options are deferred.

## Preview isolation

Preview opens a modal with a **fresh deep-copied PreviewSession**. Text, textarea, radio, checkbox, Likert and range are real controls. PageBreak projection drives Previous/Next/Finish. Required answers, maximum length, option membership and VAS bounds/step are validated; finishing rechecks all pages. VAS initial visual position is not an answer. Pointer, range input or range-navigation keys mark it touched, including interaction without changing the initial value.

Only JS memory holds answers/touched flags; no fetch, AJAX, localStorage, sessionStorage, participant, execution, submission, Storage, email, export or notifications. Closing clears the answer maps and removes the dialog; restart resets progress; reopening constructs a fresh session. Desktop/Tablet/Mobile change max-width of the same preview, not the scientific definition. Modal traps focus and restores it on close. Responses typed into canvas controls are also transient and are not copied to preview or saved.

## Native → Engine prototype mapping

`EngineMapper::map` validates native input and constructs an immutable `StudyVersionDefinition` directly. No `parse_blocks`, TemplateAdapter, Gutenberg post, execution or database writes. It creates deterministic wrapper Macro/assessment IDs; native elements retain node IDs, parent relationships and sibling positions. Native groups map to nonrandom structural Micro GROUP nodes **only as an export representation**; this does not decide future scientific group semantics or wire them into existing Builder. Native PageBreak maps to PAGE_BREAK directive. Content snapshots and protocol_metadata preserve the entire canonical native definition, including option identities, group hierarchy and VAS config.

| Native type | Existing contract | Boundary |
|---|---|---|
| text / textarea | TEXT | max_length; native widget config in snapshot |
| single_choice | CHOICE | ordered stable option IDs |
| likert | INTEGER | bounds 1..N; option IDs/labels preserved in native snapshot; future response adapter must explicitly map option ID to ordinal |
| vas | NUMBER | numeric min/max; step/initial/labels preserved in snapshot, not newly enforced by existing Engine |
| instruction / image placeholder | CONTENT TEXT | native snapshot; placeholder is not durable MEDIA |
| group | MICRO GROUP | structural, sequential, no schedule/randomization |
| page_break | PAGE_BREAK | no execution, target or answer |
| multiple_choice | unsupported | whole export rejected; never collapse array, split questions or drop options |

The adapter demonstrates a valid existing definition for the supported subset and deterministic roundtrip. It is **not a production execution integration**: current runtime does not yet consume native widget contracts. No UI publish/export button is exposed in this prototype. Native multiple choice remains fully editable/saveable/previewable. Runtime integration requires explicit contract work after product review.

## Tests and manual acceptance

`tests/assessment-editor/runtime-dom.js`: model identity/tree/reorder/clone/delete/pages/canonicalization plus real DOM insertion/drop/selection/inline/options/inspector/save/load/error/preview controls/navigation/reset/touched/width/XSS. Preview tests assert transport call count does not change.

`tests/run-assessment-editor.php`: authoritative validation, duplicate/malformed DTO rejection, permissions, persistence/revision CAS, native→Engine contract/roundtrip and real authenticated HTTP AJAX/screen/nonce/Origin checks. Uses only the existing disposable M0 fixtures; never run its installer against a personal WordPress database. `tests/ci/run.sh full` includes both suites plus all existing suites/build/clean/upgrade/smoke/lifecycle and strict RCT.

Manual route: new evaluation → drag Text → write label → Single Choice/options → Likert → VAS → group/move children → PageBreak → question on page 2 → drag reorder → duplicate → save → reload/open → Preview → answer/Next/back/finish → close → reopen/confirm empty. Test in the user's Firefox/Windows environment. Automated DOM and backend checks do not certify layout or product acceptance.
